Setup y administración de Data 360

Permisos, data spaces, Data Cloud One, ciclo de vida con data kits, gobernanza y diagnóstico.

🎯 Objetivos del módulo (según la guía oficial del examen)
  • Configurar permisos, permission sets y ajustes de la org.
  • Aplicar requisitos de gobierno a la configuración.
  • Gestionar el ciclo de desarrollo con las herramientas disponibles.
  • Diagnosticar problemas comunes.

La lista de permission sets cambió entre septiembre y noviembre de 2025 (ver artículo «License, Credits, and Permission Set Changes»). Verifica los nombres en Setup de la org concreta ⚠ verificar.

Límites relacionados Help

  • 200.000 permission sets de Data 360 y 200.000 adicionales de Data Aware Specialist (licencias).
  • Permission sets de data space: 1 por data space; no pueden incluirse en permission set groups ni cuentan contra el límite de licencias.
  • Orgs no soportadas: Professional Edition y Government Cloud.

🛡️ 2.3 Gobernanza y seguridad

Elementos de gobierno Glosario

  • Process definitions: flujos estandarizados que gestionan streams, transformaciones, insights, segmentos e identity resolution.
  • Data lineage / record lineage: traza de cómo fluyen los datos entre objetos (upstream/downstream) y de dónde viene cada registro (Data Source, Data Source Object, Internal Organization).
  • Allowlist / blocklist de IP, dominios o emails para acceso a la instancia.
  • External Key Management (EKM): claves raíz gestionadas por el cliente en AWS KMS.
  • Private Connect: conectividad privada con sistemas externos para federación y acceso a datos (1 ruta incluida).
  • Consent management y communication capping.

🔧 2.4 Ciclo de vida y troubleshooting

Herramientas Glosario

  • Data Explorer: ver datos de un DMO, DLO o CIO (10 columnas por consulta, 100 filas por página Help).
  • Query Editor: SQL sobre DLO, DMO, CIO y data graphs.
  • Profile Explorer: inspeccionar Unified Individuals.
  • Data Lens: consultas y gráficos sin informe estático.
  • Processing History del ruleset: tasas de matching y consolidación Trailhead.
  • Data kits + Package Manager para promoción entre entornos; Code Extensions para transformaciones personalizadas.

Checklist de diagnóstico ⚠ verificar

  • ¿El campo está mapeado a un DMO? Sólo lo mapeado sirve para segmentar y activar Glosario.
  • ¿El data stream refresca? Revisa programación y errores.
  • ¿El ruleset ha corrido? Los jobs se omiten si no hay cambios.
  • ¿El segmento supera algún límite (rapid: 7 días de eventos; standard: 24 meses)?
  • ¿La activación hereda consentimiento/capping?
