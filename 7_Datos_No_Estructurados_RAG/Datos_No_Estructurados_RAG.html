Reglas prácticas Trailhead

  • Un retriever individual lee de un único search index; un search index indexa un único DMO. Para varias fuentes → ensemble retriever.
  • Se crea automáticamente un retriever por índice.
  • Recomendación del trail avanzado: índice híbrido e indexar sólo campos de texto largo.

🛠️ 7.3 Pipeline y buenas prácticas

Pipeline Trailhead

  • Ingestar documentos (UDLO/UDMO) →
  • Chunking →
  • Vectorización (embeddings) →
  • Índice (vector/hybrid/enriched) →
  • Retriever →
  • Prompt template / agente con grounding →
  • Respuesta con citations.

Buenas prácticas generales de RAG ⚠ verificar

  • Limpia, deduplica y versiona las fuentes; prioriza documentos autoritativos.
  • Itera el tamaño y solape de chunk con preguntas reales; mide si el pasaje correcto aparece en el top-k.
  • Usa híbrido si hay SKUs, códigos o nombres propios; añade enriquecimiento si compensa el coste.
  • Filtra por metadatos y permisos para no exponer contenido a quien no corresponde (dynamic filters).
  • Evalúa de forma continua: fidelidad a la fuente, relevancia, tasa de «no sé».
  • Combina el contexto no estructurado con datos unificados del cliente (data graph) para personalizar.

🧪 Autoevaluación

¿Cuándo preferir un índice híbrido?

Cuando las consultas combinan significado y términos exactos.

¿Cómo agrego varias fuentes a un mismo grounding?

Con un ensemble retriever.

¿Qué aporta el enriched index y qué cuesta?

Mejor precisión mediante chunks de metadatos/preguntas; consume Flex Credits.

¿Qué hace el hybrid search autodrop?

Descarta resultados tras una caída brusca de relevancia.
