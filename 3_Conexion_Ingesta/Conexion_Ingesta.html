🌱 Para entender: cómo entran los datos

💡 Analogía. Una aduana: el data stream es la puerta por la que entra la mercancía; el DLO es el almacén donde queda tal cual llegó; los transforms son la inspección y limpieza; el mapeo es traducir cada producto al catálogo común (DMO).

La decisión más importante: la categoría

  • Profile: «quién» (personas, cuentas). Sirve para segmentar y unificar.
  • Engagement: «qué hizo y cuándo» (pedidos, clics). Necesita un campo fecha/hora.
  • Other: «contexto» (productos, tiendas).
  • Se elige al crear el stream y no se puede cambiar.

🔗 3.1 Pasos de conexión

Los cuatro pasos Trailhead

  • Crear la conexión: admin o usuario con permiso Data Cloud Architect instala data bundles, añade configuración/autenticación o crea definiciones de eventos.
  • Crear el data stream: cada conexión puede tener streams que crean DLO para datos, metadatos o ambos.
  • Transformar: key qualifiers, fórmulas simples, transforms batch o streaming.
  • Mapear: a Customer 360 Data Model; algunos conectores vienen premapeados. Obligatorio para rulesets de identidad.
Tipo de conector TrailheadEjemplos
Conectores Salesforce, servicios y tercerosStreaming o batch
Zero Copy Data FederationSin almacenar datos; crea un DLO externo con sólo metadatos
Targets (salida)SFTP, Marketing Cloud Engagement, plataformas de publicidad, data actions, data shares (BigQuery, Snowflake)

Categorías de data stream Trailhead

  • Streaming (casi tiempo real, p.ej. web).
  • Batch (programado).
  • Federated (DLO sólo de metadatos).
Los datos se almacenan tal cual, con su estructura y tipos de origen. Antes de segmentar, analizar o activar hay que mapearlos al modelo Trailhead.

🏷️ 3.2 Categoría, claves y bundles

Categoría HelpPara quéMapeo requerido

Examen: la categoría no se puede cambiar tras guardar el stream HelpGlosario.

Claves Glosario

  • Primary key: identificador único del registro (email, SKU).
  • Composite key: clave formada por varios campos, generada con una fórmula en la ingesta.
  • Key qualifier / Fully Qualified Key (FQK): clave compuesta de clave origen + qualifier que identifica la fuente; evita conflictos de claves al armonizar datos de orígenes distintos.
  • Data bundle: conjunto de data streams mapeados automáticamente (p.ej. Salesforce CRM).

🪞 3.5 Zero Copy y colaboración de datos

Concepto GlosarioDescripción
Query federation (live)Data 360 envía la consulta al sistema externo en tiempo de ejecución; sin almacenar datos
Accelerated query federationMantiene una caché local refrescada periódicamente y consulta sobre ella
File federationLee ficheros del almacenamiento externo mediante tablas virtuales, sin ingestarlos
External DLOContenedor de metadatos que apunta a los datos externos
Data shareColección de DLO, DMO y CIO que permite consultar sin sacar datos de Data 360
Clean roomEntorno para colaborar entre propietarios de datos sin compartir los datos en bruto

Plataformas y reglas TrailheadHelp

  • Fuentes mencionadas: Snowflake, Databricks, BigQuery y Amazon Redshift; todo sistema externo admite query federation, no todos file federation.
  • Por defecto es live query (no se persiste nada); la caché es opcional en query federation; file federation siempre es live.
  • Data shares hacia fuera: p.ej. BigQuery y Snowflake. Límites: 100 shares por org, 20 targets, 250 objetos por share.
  • Sin consumo de créditos de federación/sharing si consulta y origen están en la misma región y nube.

🧪 Autoevaluación

Un stream de pedidos con fecha de compra, ¿qué categoría?

Engagement (serie temporal con event datetime obligatorio).

¿Puede cambiarse la categoría de un data stream ya guardado?

No.

¿Qué devuelve la Ingestion API de streaming si la petición supera 200 KB?

HTTP 403.

¿Qué guarda un external DLO?

Sólo metadatos que apuntan a los datos en el sistema externo.

¿Streaming o batch transform para limpiar al llegar cada registro?

Streaming transform.

⚡ Repaso exprés (lo que debes saber de memoria)
