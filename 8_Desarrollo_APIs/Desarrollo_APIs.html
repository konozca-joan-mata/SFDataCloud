Perfil Developer: APIs, SQL y extensiones

Ingestion API, Query API, Connect REST API, Query Editor, transforms con SQL, code extensions y empaquetado.

🎯 Objetivos del módulo (según la guía oficial del examen)
  • Elegir la API adecuada.
  • Escribir SQL en Query Editor y transforms.
  • Conocer los límites de ejecución.
  • Automatizar el despliegue con data kits.

🌱 Para entender: qué API para qué

Quiero…Uso…
Enviar datos de mi sistema a Data 360Ingestion API (streaming: pocos registros frecuentes; bulk: cargas grandes)
Leer datos o insights desde otra aplicaciónQuery API / JDBC
Orquestar tareas (consultas, activar audiencias, pipelines) por códigoConnect REST API
Transformar con lógica que SQL no cubreCode Extensions
Reaccionar a cambiosData actions + Platform Events

Flujo mental de una llamada autenticada

  • Tu aplicación se autentica en Salesforce (OAuth, normalmente con una connected/external client app).
  • Obtiene un token válido para Data 360 (el flujo exacto: consúltalo en Developer docs).
  • Llama al endpoint con el token; si recibes 403 o 429, revisa tamaño y ritmo.
📦 Caso Mediterránea. El e-commerce de Mediterránea envía cada compra a la Ingestion API de streaming (JSON pequeño, cientos por minuto) y cada noche una carga bulk con el histórico corregido.

🧪 8.2 Ejemplos ilustrativos

# Ingestion API (streaming) — patrón. Rutas y versión: verifica en Developer docs
curl -X POST "$DC_TENANT/api/v1/ingest/sources/<source_api_name>/<object_name>" \
  -H "Authorization: Bearer $DC_TOKEN" -H "Content-Type: application/json" \
  -d '{"data":[{"id":"1001","email":"ana@example.com","created":"2026-11-02T10:00:00Z"}]}'
# Límites: 200 KB por petición (403 si se excede) y 250 req/s en total (429)
-- Streaming transform ilustrativo: normalizar email al llegar
SELECT
  id__c,
  LOWER(TRIM(email__c)) AS email_clean__c,
  created__c
FROM Customers_Stream__dll
Los sufijos de API name son __dll (DLO), __dlm (DMO) y __cio (CIO).

📦 8.3 ALM y calidad

Despliegue Help

  • Data kit en el data space por defecto → Package Manager → org destino.
  • Máx. 50 objetos por operación de guardado en un kit; transforms ligadas a data spaces no por defecto no se despliegan con kit.
  • Prueba en sandbox: mapeos, rulesets y segmentos con datos representativos.
  • Versiona OpenAPI schemas y SQL de insights/transforms en Git.

🧪 Laboratorio 8 · Primera llamada (opcional)

Requiere una org con Data 360 y una app de integración. Sigue la guía oficial de Ingestion API DevDocs; aquí sólo el esquema de trabajo.

Comprobación: ves tus registros en el DLO y entiendes por qué no son inmediatos.

⚡ Repaso exprés (lo que debes saber de memoria)

  • Streaming: JSON ≤ 200 KB, 250 req/s, procesado ~3 min; bulk CSV ≤ 150 MB.
  • Ingestion API = upsert; sin full refresh manual.
  • Query API: CI paginado, hasta 4.999 filas por consulta.
  • Code extension: función 5 min, script 12 h, paquete 5 GB.

Fuentes: Developer docs: Data 360 Integration Guide (Ingestion API, Query API); Help: glosario y límites. Los ejemplos de código son ilustrativos: confirma rutas y versiones en developer.salesforce.com/docs/data.
